🖥️ Windows GPU Worker 启动指南

前提条件

  • Windows 10/11 + NVIDIA GPU（≥8GB 显存，推荐 RTX 3060 12GB）
  • Python 3.10+（不要用 3.14，PyTorch 不兼容）
  • NVIDIA 驱动已安装（nvidia-smi 可正常输出）
  • WireGuard 隧道已连接（能 ping 10.100.0.1）

首次安装

# 1. 下载 Worker 文件
# 从 VPS 下载（通过 WireGuard）
scp ubuntu@10.100.0.1:/home/ubuntu/qwen-tts-worker.zip C:\qwen-tts-worker.zip

# 2. 解压
mkdir C:\qwen-tts-worker
cd C:\qwen-tts-worker
tar -xf ..\qwen-tts-worker.zip --strip-components=1

# 3. 创建 Python 3.10 虚拟环境
py -3.10 -m venv .venv

# 4. 安装 PyTorch（CUDA 12.1，约 2.4GB）
.venv\Scripts\pip install torch==2.2.1 --index-url https://download.pytorch.org/whl/cu121

# 5. 安装其余依赖
.venv\Scripts\pip install -r worker\requirements.txt

# 6. 安装匹配的 torchaudio
.venv\Scripts\pip install "numpy<2" torchaudio==2.2.1 --index-url https://download.pytorch.org/whl/cu121

# 7. 预下载模型（约 3.5GB，用镜像加速）
set HF_ENDPOINT=https://hf-mirror.com
.venv\Scripts\python worker\download_models.py
⚠️ 常见坑：
  • numpy 必须降级到 <2（torch 2.2.1 不兼容 numpy 2.x）
  • torchaudio 版本必须和 torch 一致（都是 2.2.1）
  • Flash Attention 在 Windows 上可不装，Worker 会自动回退
  • Windows 需能访问 HuggingFace 或设置镜像 HF_ENDPOINT=https://hf-mirror.com

日常启动

# 方式1：双击 bat 文件
C:\qwen-tts-worker\run_worker.bat

# 方式2：命令行启动（懒加载模式，推荐）
cd C:\qwen-tts-worker
set HF_ENDPOINT=https://hf-mirror.com
.venv\Scripts\python worker\start_worker.py --host 0.0.0.0 --port 8001 --device cuda:0

# 方式3：预加载模式（启动时加载模型，首次请求更快）
.venv\Scripts\python worker\start_worker.py --preload

# 方式4：开机自启（Windows 计划任务）
schtasks /create /tn QwenWorker /tr C:\qwen-tts-worker\run_worker.bat /sc onstart /ru Administrator /f
schtasks /run /tn QwenWorker

🌊 API 流式输出

流式输出通过 Server-Sent Events (SSE) 实现，生成完成后分块返回音频，减少客户端等待时间。

端点

功能端点方法
CustomVoice 流式/api/v1/custom-voice/generate-streamPOST
VoiceDesign 流式/api/v1/voice-design/generate-streamPOST
VoiceClone 流式/api/v1/base/clone-streamPOST

curl 示例

curl -X POST http://124.221.52.32:8000/api/v1/custom-voice/generate-stream \
  -H "Content-Type: application/json" \
  -d '{"text":"你好世界","language":"Chinese","speaker":"Serena"}'

SSE 事件格式

# 1. 元数据事件（生成完成后发送）
event: metadata
data: {"sample_rate":24000,"generation_time":7.3,"audio_duration":2.3}

# 2. 音频块事件（每 0.5 秒一块，base64 编码的 WAV）
event: audio
data: UklGRiQAAABXQVZFZm10...

# 3. 完成事件
event: done
data: complete

JavaScript 示例

const response = await fetch('/api/v1/custom-voice/generate-stream', {
  method: 'POST',
  headers: {'Content-Type': 'application/json'},
  body: JSON.stringify({
    text: '你好世界',
    language: 'Chinese',
    speaker: 'Serena'
  })
});

const reader = response.body.getReader();
const decoder = new TextDecoder();
const audioChunks = [];
let sampleRate = 24000;

while (true) {
  const {done, value} = await reader.read();
  if (done) break;
  const text = decoder.decode(value);
  const lines = text.split('\n');
  for (const line of lines) {
    if (line.startsWith('data: ')) {
      const data = line.slice(6);
      if (data !== 'complete') {
        // base64 解码为 WAV blob
        const bytes = atob(data);
        const buf = new Uint8Array(bytes.length);
        for (let i = 0; i < bytes.length; i++)
          buf[i] = bytes.charCodeAt(i);
        audioChunks.push(buf);
      }
    }
  }
}

// 合并所有音频块并播放
const blob = new Blob(audioChunks, {type: 'audio/wav'});
audio.src = URL.createObjectURL(blob);
audio.play();
💡 说明：当前实现的"流式"是伪流式--模型先生成完整音频，再分块发送。真正的流式推理（边生成边输出）需要 Qwen3-TTS 模型本身支持流式 token 生成，目前 qwen-tts 库尚未提供此能力。

⚡ 提高生成速度

1. 预加载模型 推荐

Worker 启动时直接加载模型到显存，避免首次请求等待。

.venv\Scripts\python worker\start_worker.py --preload

代价：Worker 启动慢（约 10 秒），但首次请求和后续请求一样快。

2. 使用 Flash Attention 2 +30% 速度

Flash Attention 可以显著加速 Transformer 推理，减少显存占用。

# Linux 上安装较简单
pip install flash-attn>=2.5.0 --no-build-isolation

# Windows 上较困难，可选方案：
# 1. 使用预编译 wheel: https://github.com/bdashore3/FlashAttention-Windows
# 2. 使用 WSL2 + Linux 环境
# 3. 不装也可以用，Worker 会自动回退到标准 attention

3. 减小模型精度 省显存

默认 bfloat16，可以改为 float16 进一步省显存（质量略降）。

# 在 worker.py 或环境变量中设置
set MODEL_DTYPE=float16

4. 短文本分段并行 长文本优化

对于长文本，可以在客户端按句号/逗号分段，并行发送多个请求。

import asyncio, httpx

async def batch_generate(texts, speaker="Serena"):
    async with httpx.AsyncClient() as client:
        tasks = [
            client.post("http://124.221.52.32:8000/api/v1/custom-voice/generate",
                json={"text": t, "speaker": speaker, "response_format": "base64"})
            for t in texts
        ]
        results = await asyncio.gather(*tasks)
        return [r.json() for r in results]

# 使用
texts = ["第一句。", "第二句。", "第三句。"]
results = asyncio.run(batch_generate(texts))

🏗️ 架构说明

┌──────────┐     HTTP/HTTPS      ┌─────────────────┐    WireGuard     ┌──────────────────┐
│  客户端   │ ──────────────────→ │  VPS :8000      │ ──────────────→ │  Windows :8001   │
│ 浏览器/App│    124.221.52.32    │  (业务层)        │   10.100.0.x     │  (GPU Worker)    │
└──────────┘                     │                 │   ~20ms 延迟     │                  │
                                 │  • API 鉴权     │                  │  • 模型加载      │
                                 │  • Demo WebUI   │                  │  • GPU 推理      │
                                 │  • 音频预处理   │                  │  • RTX 3060 12GB │
                                 │  • 请求转发     │                  │                  │
                                 │  • 无需 GPU     │                  │  • 无需公网IP    │
                                 └─────────────────┘                  └──────────────────┘

数据流

  1. 客户端 → VPS:8000 发送 POST 请求
  2. VPS 预处理音频（裁剪/去噪/归一化）
  3. VPS → Worker:8001 通过 WireGuard 转发（HTTP，~20ms）
  4. Worker 加载模型（首次）+ 执行推理
  5. Worker 返回 WAV 音频
  6. VPS 格式化响应 → 返回客户端

🔧 故障排查

Worker 连不上

# 1. 检查 WireGuard 隧道
ping 10.100.0.2          # 从 VPS ping Windows
ping 10.100.0.1          # 从 Windows ping VPS

# 2. 检查 Worker 是否运行
curl http://10.100.0.2:8001/health

# 3. 检查 Windows 防火墙
# PowerShell（管理员）:
Get-NetFirewallRule -DisplayName "*SSH*"
New-NetFirewallRule -DisplayName "TTS Worker" -Direction Inbound -LocalPort 8001 -Protocol TCP -Action Allow

模型加载超时

如果 Windows 无法访问 huggingface.co，模型加载会反复超时。解决方案：
  • 设置镜像：set HF_ENDPOINT=https://hf-mirror.com
  • 或开启代理后预下载模型：python worker\download_models.py
  • 注意：不能设 HF_HUB_OFFLINE=1，transformers 4.57.x 有 bug

NumPy 不兼容

# 报错: "A module compiled using NumPy 1.x cannot be run in NumPy 2.x"
pip install "numpy<2"

torchaudio WinError 127

# 报错: "OSError: [WinError 127] 找不到指定的程序"
# 原因: torchaudio 版本和 torch 不匹配
pip install torchaudio==2.2.1 --index-url https://download.pytorch.org/whl/cu121

VPS 路由问题（Docker 环境）

# 如果 wg-easy 运行在 Docker bridge 网络（非 host 模式）
# VPS 主机无法直接访问 10.100.0.x，需要添加路由 + NAT

# 1. 添加主机路由
WG_IP=$(docker inspect wg-easy --format '{{range .NetworkSettings.Networks}}{{.IPAddress}}{{end}}')
sudo ip route add 10.100.0.0/24 via $WG_IP

# 2. 容器内添加 NAT（让主机源地址被 SNAT）
docker exec wg-easy iptables -t nat -A POSTROUTING -d 10.100.0.0/24 -j MASQUERADE

WireGuard 隧道频繁断开

# 在 Windows 的 WireGuard 配置中添加 Keepalive
[Peer]
...
PersistentKeepalive = 25   # 每25秒发心跳，防止 NAT 超时

🐍 Python 调用示例

import httpx

API_URL = "http://124.221.52.32:8000"

# 基本生成
with httpx.Client() as client:
    resp = client.post(f"{API_URL}/api/v1/custom-voice/generate",
        json={"text": "你好世界", "speaker": "Serena", "response_format": "wav"},
        timeout=300)
    with open("output.wav", "wb") as f:
        f.write(resp.content)

# 异步批量生成
import asyncio

async def batch_tts(texts):
    async with httpx.AsyncClient() as client:
        tasks = [
            client.post(f"{API_URL}/api/v1/custom-voice/generate",
                json={"text": t, "speaker": "Serena"},
                timeout=300)
            for t in texts
        ]
        return await asyncio.gather(*tasks)

results = asyncio.run(batch_tts(["第一句", "第二句"]))
